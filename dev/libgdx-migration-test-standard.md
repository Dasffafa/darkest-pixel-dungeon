# Darkest Pixel Dungeon LibGDX 迁移测试标准

## 1. 用途与基准

本标准用于验收 LibGDX 迁移的阶段成果和最终版本。它验证底层替换没有意外改变
DPD 的玩法、数值、存档和视觉行为，同时验证新增 Desktop 平台能力。

Android 现版本 App 是运行行为的权威基准。测试时在同一手机上使用相同语言、方向、
字体选项、沉浸模式、音量和等价游戏状态，对现版本与迁移版进行 A/B 对比。Desktop
没有旧版本时，以 Android 现版本行为及本标准中的跨平台要求为准。

测试存档必须先复制备份。禁止用用户唯一一份存档直接测试迁移版本。

## 2. 结果分级

| 等级 | 定义 | 处理 |
|---|---|---|
| P0 阻断 | 无法启动、崩溃、黑屏、存档损坏、核心流程无法继续 | 当前阶段不得通过，停止后续迁移 |
| P1 严重 | 玩法语义变化、输入不可用、主要画面错误、持续音频或生命周期异常 | 当前阶段不得通过 |
| P2 一般 | 局部错位、字体溢出、轻微资源或平台行为问题 | 记录并在 M8 前修复；影响专项目标时不得通过 |
| P3 可接受 | 平台天然差异或经明确批准的微小差异 | 记录原因后可通过 |

未经明确批准，不得把“现代 Shattered/Radish 就是这样”作为接受行为差异的理由。

## 3. 通用测试条件

每次报告必须记录：

- 被测提交、平台、构建类型、设备/操作系统。
- Android 的分辨率、方向、显示缩放、语言、字体和沉浸模式。
- Desktop 的窗口尺寸、窗口化/全屏状态、显示缩放和语言。
- 测试用存档是新建、复制的旧存档还是调试场景。
- 首个失败的完整错误堆栈、操作步骤和截图；不要只提供日志末尾。

阶段专项测试覆盖该阶段已经存在的平台。M1-M5 以 Android 为运行门禁；Desktop
建立后，M6-M8 至少各执行一次 Android 和一次 Desktop，并补测共享底层的既有用例。

## 4. 核心测试场景

| 编号 | 场景 | 关键观察点 |
|---|---|---|
| S01 | 冷启动到标题/欢迎场景 | 初始化、首帧、Logo、音乐、无闪烁或黑屏 |
| S02 | 创建角色并进入固定地牢 | 文本、按钮、场景切换、加载、玩家出生位置 |
| S03 | 地牢移动与交互 | 点击寻路、等待、拾取、开门、攻击、动画时序 |
| S04 | 背包和物品窗口 | 滚动、选择、取消、长文本、遮罩和裁剪 |
| S05 | 暂停与恢复 | 场景、音频、纹理、Shader、计时不重复或丢失 |
| S06 | 保存、退出和继续 | 进度、背包、Buff、地图、随机状态可继续 |
| S07 | Boss 或高特效场景 | 混合、光照、粒子、震屏、音效、帧稳定性 |
| S08 | 结算/排名/徽章 | 文件写入、反射恢复、长列表和文本布局 |
| S09 | 设置与语言/字体切换 | 即时生效、重建场景、无乱码和资源泄漏迹象 |
| S10 | 异常路径 | 返回键、焦点丢失、锁屏、重复启动和异常退出 |

首个垂直切片固定为 S01 → S02 → S03：从标题/欢迎场景创建角色，进入一个固定地牢
并完成移动、拾取、开门和一次战斗。

## 5. 功能验收

### 5.1 启动与生命周期

- 冷启动和第二次启动均进入正确场景，不重复初始化资源。
- 后台/前台、锁屏/解锁、窗口失焦/恢复后保持当前场景和游戏进度。
- 恢复后不会出现双重音乐、失效音效、黑纹理、丢失 Shader 或速度突变。
- 正常退出与再次启动不会损坏设置和存档。
- Android 返回键保持现版本的窗口关闭、返回或退出语义。

### 5.2 输入

- Android 点击、长按、拖动和边缘取消与现版本一致。
- Desktop 鼠标左键完成主要触摸操作；滚轮可操作可滚动内容。
- Desktop 键盘可完成返回/取消及计划定义的基础地牢操作。
- 按下和释放不会重复触发，场景切换时不会遗留输入事件。
- 模态窗口打开时，输入不会穿透到地牢或下层 UI。

### 5.3 玩法与时序

- 相同操作的行动消耗、回合顺序、伤害和状态变化不因迁移而改变。
- 场景切换、淡入淡出、Tweener、Actor 更新及动画完成回调顺序一致。
- 暂停期间不推进游戏时间，恢复首帧不会产生异常的大时间步长。
- 迁移提交不得包含未经批准的数值、掉落、地图或敌人行为变化。

### 5.4 渲染与视觉

- Tilemap、角色、物品、UI、粒子、遮罩、光照和文本均完整显示。
- 与现版本并排比较时，无系统性的像素偏移、模糊、纹理渗色或比例变化。
- 最近邻/线性过滤选择、透明边缘、纹理环绕和图集区域正确。
- blend、scissor 和绘制顺序正确；窗口内容不会越界或错误遮挡。
- Android 旋转/重建和 Desktop resize 后 viewport、相机和像素比例正确。
- 上下文恢复后纹理、VBO、字体与 Shader 全部重新可用。

允许 Desktop 因显示比例产生边缘留白；不允许拉伸像素或改变可见游戏区域导致玩法差异。

### 5.5 资源、文件与存档

- Android 与 Desktop 使用相同的只读游戏资源，资源路径大小写完全匹配。
- 平台用户数据写入各自正确目录，不写入资源目录或覆盖测试原件。
- 新存档能保存、退出、加载并继续；备份恢复路径有效。
- 复制的现版本 Android 存档能被迁移版读取，关键状态与现版本一致。
- 类名、Bundle 字段缺失或未知类型有明确错误，不得静默覆盖原存档。
- 排名、徽章、设置和异常报告文件分别验证读写。

### 5.6 音频

- 音乐、短音效、循环、音量和静音与现版本一致。
- 切换场景时音乐正确停止、保持或替换，不重叠播放。
- 后台/前台和焦点切换时按平台预期暂停恢复。
- 高频连续音效不会崩溃或永久占用音频通道。
- Desktop 所有主要音频资源均可加载，不受文件名大小写影响。

### 5.7 字体与文本输入

- 中文、英文及项目主要目标语言无乱码、缺字崩溃或不可读回退。
- 字体基线、字距、换行和像素过滤与现版本等价。
- 标题、按钮、背包说明、长窗口和排名列表不存在溢出或遮挡。
- 运行时切换语言/字体后已有场景与新场景均正确更新。
- Android 软键盘与 Desktop 文本输入均支持确认和取消，不遗留焦点。

### 5.8 Shader、滤镜与特殊动画

- Shader 在 Android 与 Desktop 均编译；失败时有日志和可用降级路径。
- Uniform 随帧、场景和 resize 正确更新，不使用已释放资源。
- 恒等全屏滤镜开启与关闭时画面像素一致。
- 滤镜链顺序、强度、开关和低性能降级可重复验证。
- 场景切换、暂停恢复和上下文恢复后效果仍有效。
- 关闭新增效果后不得残留颜色、混合状态或性能副作用。

### 5.9 平台服务

- Android URL、震动、方向、沉浸模式和 Firebase/崩溃报告保持可用。
- Desktop URL、日志、剪贴板等已声明能力可用；不支持项必须无害降级。
- `core` 和 `SPD-classes` 不得因 Desktop 启动而加载 Android 类。

## 6. 尺寸与平台矩阵

Android 至少覆盖当前手机的竖屏常用配置，并验证一次横屏设置切换。Desktop 至少覆盖：

- 1280×720 窗口化。
- 1920×1080 窗口化或全屏。
- 小窗口缩放到计划允许的最小尺寸。
- 高 DPI 环境（具备设备时）。

所有配置均检查 UI 边界、可点击区域、像素比例和文本布局。

## 7. 阶段门禁

| 阶段 | 必须通过的范围 |
|---|---|
| M1 | Android S01-S03；首个 LibGDX 垂直切片的输入、渲染和基础音频 |
| M2 | Android S01-S05、S10；早期迁移修复、生命周期和输入 |
| M3 | Android S01-S05；宿主拆分后行为不变，平台边界静态检查 |
| M4 | S06、S08；新旧存档、设置、平台路径和反射 |
| M5 | Android S01、S02、S04、S08、S09；文本输入、字体和模块中立化 |
| M6 | Android/Desktop S01-S06、S08-S10；文件、音频、输入和基础流程 |
| M7 | 双平台 S03、S05、S07、S09；动态字体、Shader、恒等滤镜、效果开关和降级 |
| M8 | S01-S10、全部尺寸/平台矩阵和发布配置 |

任一阶段存在 P0/P1 时不得标记完成。P2 必须登记负责人和解决阶段；M8 发布候选不得保留
影响主要流程、存档或主要视觉的 P2。P3 必须写明平台原因或批准结论。

## 8. 测试报告格式

每轮验收采用以下最小格式：

```text
Commit:
Platform/device:
Build type:
Settings and save source:
Cases passed:
Cases failed:
First complete stack trace or reproduction:
Comparison with current Android app:
Severity:
Decision: pass / fail / pass with approved differences
```

阶段通过后，将报告结论、已批准差异和遗留 P2/P3 写入阶段记录，再决定是否提交该阶段。
